## Lshell 产品设计（阶段 1）

用户要开发一款 Windows 桌面 SSH 客户端，Lshell。完成产品设计文档：`docs/product-design.md`。

**已确认的需求边界（用户决策）**
- 平台：先只做 Windows，暂不考虑跨平台
- 技术栈：用户未定，调研后给出建议并采纳 Tauri 2 + Rust(russh) + React + xterm.js
- 凭据存储：主密码 + 本地加密库（Argon2id + AES-256-GCM）
- 首版能力：SFTP 面板、主机分组与标签、端口转发；**不含** OpenSSH config 导入

**关键选型结论（后续开发需遵循）**
- 协议层用 `russh` 而非 `ssh2/libssh2`：libssh2 在 Windows 走 WinCNG 不支持 ed25519 与加密 OpenSSH 格式私钥，规避它需要捆绑 OpenSSL + Perl + MSYS
- `russh` 必须锁定精确版本号（`=x.y.z`）并提交 Cargo.lock，API 不稳定
- 单条 SSH 连接上复用 shell / SFTP / direct-tcpip 三个 channel，只做一次 KEX 与主机密钥校验
- 排除「调用系统 ssh.exe」方案：拿不到 SFTP channel 与转发能力

**下一步**：阶段 1 = Tauri 工程骨架 + SQLite schema + 主机库 UI + 主密码解锁。

**环境备注**：本机 Node v22.22.2 可用，Rust/cargo 未安装（开发前需装 Rust 工具链）。

- `tsc --noEmit` 通过，`vite build` 通过（554KB / gzip 151KB）

**踩坑记录（重要）**
1. **版本锁定**：`russh` 必须 `=0.65.0`（API 不稳定）。查证发现 russh 0.65 **已移除 russh-keys**，改用 `ssh-key =0.7.0-rc.11`（预发布版）。而独立的 `russh-keys` 0.49.2 仍用 `ssh-key ^0.6`，**两者主版本不兼容**，切勿同时引入。`russh-sftp` 3.0.1 完全不依赖 russh，只要求 AsyncRead+AsyncWrite —— 这正好让 channel 复用方案成立。
2. **锁顺序死锁**：`store_secret`（vault→db）与 `load_secret`（db→vault）嵌套持锁会死锁。已改为「同时只持一把锁」，AAD 也统一为 `lshell:secret:{kind}`。
3. **Git Bash 遮蔽 MSVC 链接器**：Git 自带 GNU `link.exe`，cargo 报 `link: extra operand`。必须把 MSVC bin 放到 PATH 最前 —— 已封装 `scripts/msvc-env.sh`（自动探测 MSVC 版本与 SDK 路径）。
4. **argon2 0.6** 用 `hash_password_into` 做密钥派生（`hash_password` 是给口令哈希用的，不能用来派生密钥）。
5. **aes-gcm 0.11** 走 `aead` 0.6：`Aead` trait + `Payload{msg,aad}`。注意 `Aes256Gcm::new` 收 `&Key`，`encrypt/decrypt` 收 `&Nonce`（都要引用，不是值）。`hybrid_array::from_slice` 已废弃，改用 `TryFrom<&[u8]>`。
6. **rand 0.10** 用 `rand::fill(&mut buf)`，不再是 `rng().fill_bytes()`。
7. **主机密钥指纹**：`PublicKey::fingerprint(HashAlg::Sha256)` 直接给出 OpenSSH 格式 `SHA256:...`，无需自己算 sha2+base64。
8. **图标生成**：纯 Python 写 PNG（zlib+struct），圆角矩形判定要用有向距离场公式，逐角枚举会把象限判定和圆心配错（生成出方角）。
9. **aws-lc-rs 需要 NASM**：russh 默认启用 `aws-lc-rs`，在 Windows 编译需要 NASM 汇编器。改用 `ring` 后端（`default-features = false, features = ["flate2","ring","rsa"]`）即可去掉这个构建依赖 —— 对「简单实用」的目标是加分项。
10. **russh 0.65 的真实类型签名**（文档页面与实际源码有出入，务必看 registry 里的源码）：
    - `ChannelReadHalf` **无泛型参数**，`ChannelWriteHalf<Send>` 有
    - `Handle<H>` **不可 Clone**，内部含 `UnboundedReceiver` 也不是 `Sync` → 必须用 `Arc<tokio::sync::Mutex<Handle>>` 共享
    - `best_supported_rsa_hash()` 返回 `Result<Option<Option<HashAlg>>, _>`，**两层 Option**
    - `channel_open_direct_tcpip` 的端口参数是 `u32` 不是 `u16`
11. **crate 内 `Result` 别名会遮蔽 std**：在 `impl Trait for X` 里写 `Result<T, E>` 若模块内定义了 `type Result<T>` 别名会报「type alias takes 1 generic argument」，要用 `std::result::Result<T, E>`。

**当前状态**：Rust 库 `cargo check` 零错误零警告；7 个单元测试全部通过（vault 加解密往返、AAD 绑定、错误主密码、凭据脱敏、主机 CRUD、搜索过滤、vault_meta 往返）。前端 `tsc --noEmit` 与 `vite build` 均通过。**Release 可执行文件 7.2 MB**（目标 < 30MB 达成）。启动冒烟测试通过：9 张表 + 5 个索引自动创建。

**开发命令**：`./scripts/dev.sh`（开发模式）/ `./scripts/build.sh`（打包）。两者都基于 `scripts/msvc-env.sh` 自动加载 MSVC 环境。

用户追问「我现在都干了哪些工作，我想要的是一个桌面端 shell 工具」—— 说明此前偏重后端，界面是骨架。本轮把界面补齐并逐项验证。

**新增文件**

- `src/components/ForwardPanel.tsx` —— 端口转发管理面板

- `scripts/screenshot.py` —— ctypes + GDI 截屏（PrintWindow 抓不到 WebView2 内容）

**关键：如何看到 WebView2 界面**
PrintWindow / BitBlt 都抓不到 WebView2（独立合成进程，截图全黑）。解法是开 CDP：
```bash
WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=9222" ./lshell.exe
```
然后用 Node 内置 WebSocket 连 `http://127.0.0.1:9222/json/list` 的 webSocketDebuggerUrl，`Page.captureScreenshot` 就能拿到真实渲染结果，`Runtime.evaluate` 能读 DOM、点按钮、往 xterm 输命令。**以后做 UI 验证都走这条路。**

**本轮修掉的 4 个真 bug**
1. **终端完全没输出**（最严重）：serde 内部标记枚举不能包含序列类型 ——
   `JSON error: cannot serialize tagged newtype variant TerminalMessage::Data containing a sequence`。
   改用 Tauri 的 **Raw 二进制通道**（`InvokeResponseBody::Raw`），1 字节帧头区分数据/结束。前端收到 ArrayBuffer，直接喂 xterm。
2. **切换标签会断开连接**：原来只渲染当前标签，卸载 TerminalView 时 cleanup 调 `disconnectHost`。改为**所有标签保持挂载**，只切 `display`，并用 ResizeObserver 重新 fit。
3. **端口转发记录了请求端口而非实际绑定端口**：传 0 时返回 0，调用方连不上。改用 `listener.local_addr()` 取真实端口。
4. **SFTP 初始目录是 `/` 而不是用户主目录**：改为传 `.` 并用 `canonicalize` 解析成绝对路径。

**UI 验证结论（截图确认）**
- 终端渲染完整 Ubuntu MOTD + 语法高亮提示符 + 命令输出 ✅
- 两个标签各自独立会话（登录时间戳不同，输出互不干扰）✅
- SFTP 面板列出远端文件（26 项，含目录/文件与大小）✅
- 转发面板添加 `127.0.0.1:18080 → 127.0.0.1:22`，本地连上去收到真实 SSH 横幅 ✅

**踩坑**
- `russh_sftp::DirEntry` 自带 `metadata()`（= `FileAttributes`），字段是 `size`/`mtime`（Option），不用再发 stat 请求。
- `FileAttributes::mtime` 是字段不是方法。
- 合成 InputEvent 打字太快会乱序（"ec hHoELLO"），必须逐字符加 25ms 间隔 —— 真实用户打字不会有问题，这是测试工装的问题不是应用的问题。
- React 受控输入必须用原生 setter 改值再派发 input 事件，直接设 value 不触发 onChange。

## 打包与快捷键（2026-11-02 下午）

**打包产物**：`src-tauri/target/release/bundle/`
- `msi/Lshell_0.1.0_x64_en-US.msi` — 3.49 MiB，per-machine 安装（需管理员）
- `nsis/Lshell_0.1.0_x64-setup.exe` — 2.62 MiB，**per-user 安装（不需要管理员）**

**打包踩坑**
1. **Git Bash 会把 `/S` 改成路径**！NSIS 静默安装参数从 Git Bash 传会被 MSYS 路径转换吃掉（变成 `S:\`），安装器于是弹出一个看不见的 GUI 窗口干等 —— 表现就是「进程挂着不动、没有任何输出」。**必须用 PowerShell 调 `Start-Process -ArgumentList "/S"`，或设 `MSYS_NO_PATHCONV=1`。**
2. **MSI 是 per-machine 的**，非管理员会话装会报 `Error 1925: You do not have sufficient privileges`。所以 NSIS 配了 `installMode: "currentUser"`，这也是面向个人分发更合适的选择。
3. NSIS 语言：`languages: ["SimpChinese", "English"]`。
4. bundle identifier 从 `com.lshell.app` 改为 `com.lshell.desktop`（`.app` 后缀在 macOS 上会与 App Bundle 扩展名冲突）。
5. `tauri build` 首次会下载 WiX3 与 NSIS 工具链（从 GitHub），**很慢（本次约 15 分钟）**，之后有缓存就快了。

**快捷键的 2 个 bug**
1. `isEditing()` 把 xterm 的辅助 `<textarea>` 当成输入框 → 终端获得焦点时快捷键全部失效。改成：带 `xterm-helper-textarea` class 的元素不算「在输入框里」。
2. **`mod` 匹配写错了**：原先把 `mod` 映射到 `metaKey`，导致 `mod+k` 在 Windows 上要求按 Cmd。正确语义是 **mod = Ctrl 或 Cmd**，两者任一即可触发。

**最终验证（已安装的程序，不是开发版）**
`%LOCALAPPDATA%\Lshell\lshell.exe` 静默安装成功（退出码 0），启动后：
- 状态栏显示「已连接 test-ubuntu · 49.233.77.155:22」
- 终端执行 `uname -sr` → `Linux 7.0.0-14-generic`，`echo INSTALLED_APP_WORKS` 正常回显
- Ctrl+K 聚焦搜索框（焦点从 xterm-helper-textarea 移到 search）✅
- Ctrl+Shift+F 展开 SFTP 面板 ✅

**注意**：安装后应用仍在运行（后台任务），结束时记得 kill。

## P0 第二项落地：SFTP 拖拽上传 + 传输进度 + 取消（2026-11-03 完成）

**修掉一个既有的严重卡顿问题**
原实现把 SFTP 会话放在 `Arc<Mutex<Option<SftpSession>>>` 里，操作时全程持锁。
传输 100MB 文件期间锁被占住 → 目录列表、新建、删除全部卡死，文件面板整体僵住。
`SftpSession` 的方法都取 `&self`、内部是 `Arc<RawSftpSession>`（多路复用），
因此改成 `Arc<Mutex<Option<Arc<SftpSession>>>>`：互斥锁只保护「首次打开」那一瞬间，
拿到会话后立刻释放。这是「一条 SSH 连接 = 一组 channel」约束的必然结果。

**新增 `src-tauri/src/transfer.rs`**
- `TransferManager` / `TransferTask` / `TransferStatus` / `TransferState`
- 分块传输：64 KB 一块，每块之间检查取消标志（协作式取消，不打断协议交互）
- 取消后清理半截文件：上传删远端、下载删本地（留半截文件比失败更危险）
- 任务完成后保留 60 秒供前端展示最终状态，`start` 时顺带清理过期项

**命令层**
- `sftp_upload` / `sftp_download` 语义变了：改为后台执行并返回**传输 id**（原来阻塞返回字节数）
- 新增 `list_transfers`（前端 500ms 轮询）与 `cancel_transfer`
- `AppState` 增加 `transfers: Arc<TransferManager>` 字段
- 拖入文件夹时先检查本地路径，Rust 侧给明确提示而不是让远端报费解的错

**前端**
- `api.ts`：新增 `TransferStatus` 类型与两个命令封装
- `SftpPanel.tsx`：拖拽上传（Tauri `onDragDropEvent`）、传输进度列表、取消按钮、折叠态徽标
- 拖放事件是 **webview 级**的（整个窗口都收到），必须自己判断落点是否在面板内；
  事件坐标是物理像素，DOM 坐标是 CSS 像素，要除以 `window.devicePixelRatio`
- `components.css`：`.sftp-panel` 从 grid 改为 flex（传输列表是条件渲染的，grid 行数会错位）

**验证**
- 新增 `src-tauri/tests/transfer.rs`（真实服务器，写 /tmp 并清理）：3 项测试全通过 ——
  上传下载内容逐字节一致且进度准确 / 取消后传输停止且半截文件已清理 /
  传输期间列目录正常（实测 149ms，证明并发改造生效）
- 7 项新增 Rust 单元测试（进度累计、取消语义、状态流转、任务排序）
- Tauri 拖放事件可通过 `tauri://drag-drop` 从 JS emit（`core:event:default` 含 allow-emit），
  因此拖拽路径可用 CDP 自动化验证

**关键决策**
- 进度用轮询而非事件推送：事件有「监听器没建立就发事件」的时序问题，
  轮询在传输这种低频场景开销可忽略，且天然覆盖「传输在别处启动」的情况
- 取消是协作式的（标志位 + 分块边界检查）：不会打断到一半的协议交互

### 补记：UI 实测发现并修掉的两个缺陷（2026-11-03 晚）

**缺陷 1：取消上传会删掉用户原有的同名文件（数据丢失）**
初版实现里取消时无条件 `remove_file(远端路径)`。
若用户上传覆盖一个已存在的同名文件并中途取消，原文件被误删。
UI 实测时正好撞上：第一次上传成功创建了 drop-test.bin，
第二次同名上传被取消 —— 原文件被删掉了。

**修正**：改成「先写临时文件，成功后再改名」的原子模式。
- 上传：写 `<远端名>.lshell-part` → 成功后 `rename` 到最终位置
- 下载：写 `<本地名>.lshell-part` → 成功后 `fs::rename` 到最终位置
- 取消/失败：只删临时文件，原文件完好
- 少数 SFTP 服务器不允许 rename 覆盖已有目标 → 先删目标再改名（`replace_remote`）

集成测试新增断言：取消后远端原有的同名文件内容必须逐字节不变。

**缺陷 2：`sftp_list` 的条目路径是相对形式**
russh-sftp 的 `DirEntry::path()` 是「传给 read_dir 的路径 + 文件名」拼出来的。
原实现用用户传入的原始 path 调 `read_dir`，面板首次打开若传的是 "."，
条目路径就成了 "./xxx" 这种相对形式，删除/重命名/下载会依赖服务端 CWD，不可靠。
**修正**：改用 `canonicalize` 解析后的绝对路径调 `read_dir`。

**UI 实测结论（CDP 驱动真实应用，真实服务器）**
- 拖拽提示层正常出现（`tauri://drag-enter` + `tauri://drag-over`）
- 放下后传输列表显示：`drop-test.bin  74%  45.3 MB / 60.0 MB  2.3 MB/s  剩 6 秒`
- 取消按钮点击后状态变为「已取消」，进度停在 10.9 MB / 60.0 MB
- 拖放事件可用 CDP 自动化：从 JS `invoke('plugin:event|emit', { event: 'tauri://drag-drop', payload })`
  （`core:event:default` 含 allow-emit），这是验证拖拽路径的可行手段
- 注意：Git Bash 会把命令行参数里的 `\\` 吃成 `/`，传 Windows 路径要用正斜杠
  （`E:/data/...`），Windows API 接受正斜杠
